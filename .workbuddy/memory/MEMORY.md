## 🟡 选人层级链终态（2026-11-17 #139 · 改 ACL/选人相关代码前必读）
- **层级链**：看板层=归属部门池（None=不限）→ 板块层⊆看板 ACL → 事项层⊆板块 ACL（缺省回退看板 ACL）→ 子事项⊆父事项 owner+cc（姓名直比、**不豁免管理员**）。
- **部门约束=附加交集**：未配归属部门时池=上级 ACL 全量（不是不限！#139 修订，与前端 colPickPool 同口径）。
- **口径陷阱**：cards.owner/cc 存**姓名**（';' 分隔）、boards/board_columns 存**账号**（',' 分隔）——两层数据语义不同，过滤时必须映射（_account_name_map）。
- **写入=池外除名+响应 removed**（前端 toast）；读取=/api/me 与 visible_columns 下发前过滤。存量人员编辑放行（前端 origNames / 后端 cur 原值并入 allowed）。
- **管理员豁免**：板块/事项层 is_admin → allowed=None；子事项层不豁免。
- `PUT /boards/{bid}/acl` 只写 owner、**忽略请求里的 participants**（保留旧值设计）——设参与人走 `/participants` 端点。
- ⚠️ 测池过滤必须用**非管理员**夹具账号（admin token 触发豁免测不出）。

## 🟢 协作分工规则（2026-11-19 用户立规 · 全文见 HANDOFF §3.5）

## 🟡 测试脚本选型精准化原则（2026-11-20 T-208 梳理后用户立规 · 新增/挑选测试必读）
> 背景：T-208 全量梳理 221 个 test/ui_check 脚本 → 保留 78 / 删除 143。教训：一次性验收与复现脚本长期堆积、语义漂移测试永远红、CDP 像素断言随改版失效。
- **按风险优先，不无脑全覆盖**：优先覆盖「破坏是静默的」的服务端语义——权限/可见性口径、数据完整性（复制/导入导出/偏好/锁）、会话安全、业务流程闭环。像素级/文案类 UI 打磨**不写长命测试**，验收一次即弃（git 留痕即可）。
- **API 层优先于 CDP**：同一语义优先写 API 测试（快、稳、廉价）；CDP 仅用于无 API 等价覆盖的核心交互（选人树、筛选联动、排序设定等），并随该功能停止迭代而退役。
- **测试随功能演进同步修订**：改权限/口径/数据结构时，必须同步改引用旧语义的断言（#206 归属必选炸了 4 个旧夹具、#207-bis 下线 col_years 炸 year_layer——都是当天暴露）。修不动（如需重构操作序列适配编辑锁）→ 直接删，git 可回溯。
- **运行约定统一**：API 测试一律**从项目根运行**（`sys.path.insert('src')` + `DB='src/app.db'` 相对路径依赖）；CDP 类各自约定见文件头。失败先排查 cwd/残锁（服务内存锁跨请求残留会污染后续测试，重启 local-ctl 可清），再判断语义漂移。
- **周期性回收**：每 ~1 个月或每 10 个功能轮次做一次套件梳理（跑保留集、删永久红），防止「僵尸绿/误导红」堆积——本轮 143 个删除就是 5 周不回收的代价。
- **新测试准入检查**：① 断言语义而非实现细节（文案/坐标不写死）② 夹具自清理 + 零残留 ③ 不依赖真实业务数据形态 ④ 有明确的回归价值（改什么代码时它该红）。
