### 改了什么

用户要求：①【看板管理】移到【可选看板】之后；②【架构管理】移到【架构部门】之后；
③两个管理页面按当前成员权限动态渲染可配置范围（无权限隐藏或置灰）；④不改结构/数据/权限模型。

- **菜单顺序**：两个入口从顶栏 `.header-actions` 移到导航区 `.tb-navgroup`，
  最终 = 架构部门 → 架构管理 → 可选看板 → 看板管理 → 统计概览（新增两个 `.tb-entry-band`）
- **权限渲染（核心）**：把上一轮的 perm.py 分级模型接到前端两页。
  **判定只在后端** —— 后端算好能力位，前端只消费：
  - `/api/me` → `arch_leader_nodes` / `arch_scope` / `is_arch_owner` / `editable_boards`
  - `/api/boards` → 每看板 `can_edit` / `can_assign_owner` / `can_delete` / `perm_role` / `perm_level`
  - `/api/org/tree` → 每节点 `can_config_bind` / `can_manage_node` / `in_my_scope` / `is_leader`
  - 新增 `perm_check_pass()`（布尔版，不抛错）→ 与写接口共用 `can_do`
- **无权限三种处理**：入口无权限→**整带隐藏**；条目（架构树节点）→**置灰不可点**；
  按钮（编辑区）→**不渲染**
- **角色差异**：管理员全开 / 架构负责人只配自己管辖范围（范围外置灰）/
  看板负责人只配自己的看板且不能指定负责人 / 只读入口都看不见
- **修了一个真 bug**：`/api/boards` 原本只返回**可见**看板，而负责人=管理权但不放大可见性
  → 看板负责人打开看板管理**看不到自己负责的看板**。改为 返回 = 可见 ∪ 可管理。

### 🔴 踩到的坑

- 🔴 **入口渲染不能依赖前端列表**：`BC_BOARDS` 要打开看板管理才加载 → 首屏空 →
  把入口误判成「无权限」→ 非管理员登录后两个入口都消失。
  → 改用后端 `/api/me` 的 `editable_boards`。
- 🔴 **UI 测试就绪判据不能用静态 DOM**：`tbDepts` 在登录页就存在（静态 HTML）→
  登录失败也「就绪」→ 断言全挂。改用 `typeof ME!=='undefined' && !!ME`。
  （多个 ops/ui_check_*.py 都有这个隐患，只是它们只测 admin 才侥幸通过。）
- 🔴 **sqlite3 嵌套 execute 互相干扰**：`INSERT ... VALUES(?,(SELECT id FROM ...))`
  → 任命行没插进去 → 夹具身份不生效 → 被误判成「功能坏了」，排查方向完全跑偏。
  → 先查出来再单独执行 + **加夹具自检断言**。
- ⚠️ **token 键名是 `tk`**（login.html），不是 `token`。
- ⚠️ **越权测试要用真实 id**：假 id 先撞 404/422 把真正的 403 掩盖
  （`/api/board-config/{cid}` 的 cid 是整数，用 board_id 会 422）。
- ⚠️ **补丁脚本写文件要放最后**：断言中途失败 → 前面 edit 全丢（本轮丢过 8 处）。
- ⚠️ `local-dev.sh restart` 依旧不可靠，仍是手工 `taskkill` + 起 uvicorn。
