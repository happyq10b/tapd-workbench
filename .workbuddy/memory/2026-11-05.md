## #62 · 架构管理编辑入口调整 + 节点新增分级授权

### 用户需求（截图 + 两轮澄清）
1. 点击架构树节点 → 直接进入编辑态（标题「编辑：节点名」），去掉「节点名 · 岗位与任职」框；移除树行「编辑」按钮。
2. 「＋新增节点」仅超管可见，且是唯一能选「无上级」的入口；其他角色依靠现有上级（+子节点）。
3. 「+子节点」：架构负责人=管辖架构下所有节点；组长=自己所在组下；无权限的按钮**灰色不可点**（不隐藏）。
4. 组长在组下建组：暂不允许（用户自认失误，维持层级规则 group→∅）。

### 实现要点
- 后端 `_node_add_scope`（arch_owner ∪ binding_manager 管辖范围）+ `_check_add_parent`
  （parent_id=0 → 仅超管）+ 树接口 `can_add_child` 能力位；create 从 require_admin 放开为 require_auth+分级。
- 前端：selectOrgNode 委托 editWg（编辑态唯一实现）；+子节点 disabled 置灰；
  **置灰规则 = 权限 ∩ 层级（该类型有合法子类型）**——常规小组行对所有人置灰。
- `+子节点` 流程 `lockParentTo(pid)`：上级下拉锁成单选项（不可选「无上级」）；
  `rebuildWgParentOptions(..., allowTop)` 控制无上级选项只在新增节点流程出现。
- 非管理员新建后的板块绑定走 `PUT /api/org/nodes/{nid}/boards`（新建节点在管辖范围后代内 → 放行）。

### 教训
- **UI 测试探针别用绝对数断言**：超管视图包含生产树+夹具树，行数断言必炸 → 用「置灰状态与节点类型一一对应」的一致性断言。
- **JS 探针的引号层级**：Python 字符串 → JS 字符串 → CSS 属性选择器，三层引号要用 `'...\'button[onclick*=\'editWg\']\'...'` 风格；`\"` 双层转义会静默返回 None。
- **测试探针里不能写 Python 注释在续行外**（`'...'   // 注释` 会 SyntaxError）。

- 新增 ops/ui_check_org_entry.py **29/0**；门禁 verify.py 7/7；夹具零残留。
- 既有失败不变：ui_check_owner.py 1 项、ui_check_tree.py 1 项（stash 对照确认与本轮无关）。

## #65 · 看板管理弹窗首开尺寸异常修复
- 根因：openBoardConfigModal 先 renderBoardList 后 display:flex →
  setBcListScroll 在隐藏态用 offsetHeight 量行高 → 0 → maxHeight=20px 压扁；
  二开正常是因为值已被上次可见渲染纠正（「首开异常二开正常」= 隐藏态测量型 bug 的典型信号）。
- 修复：先显示再渲染 + setBcListScroll 隐藏态守卫（offsetParent 空则跳过）。
- **通用教训：任何依赖 offsetHeight/getComputedStyle 的适配逻辑，
  必须在元素可见后执行；隐藏态测量得 0，要么守卫跳过要么 rAF 延后。**

## #68 · wwn 可见性修复 + 可见性模型按任命链重写
- 根因：wwn 部门长+组员双重身份，组级绑定白名单把部门长权限收窄到 1 板
  —— 多重身份未取最高权限。
- 新模型：可见 = 公共(财务中心/未归属) ∪ 负责范围 ∪ 看板负责人/参与人；
  部门成员不再自动继承部门看板；组白名单收窄层移除（并集模型保证最高权限）。
- 通用教训：
  1. **多重身份权限判定必须取并集（最高权限）**，收窄型白名单只对
     「无更高身份」的人生效——否则低层级身份会裁剪高层级权限（wwn 案）。
  2. 三层探针法（逐层打印可见集）是定位可见性 bug 最快路径。
  3. 测试断言硬编码「无归属→0 看板」被生产数据（综合移入财务中心）打破
     —— 公共看板必须动态实测基线，不得硬编码。
- 验证：7 测试断言同步全绿；verify.py 7/7；夹具零残留。
