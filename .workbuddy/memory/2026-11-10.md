## #118 统计卡实时刷新修复（src 提交 bf5aed9）
- 现象：四张统计卡（总事项/已完成/进行中/未完成）只在 F5 后更新
- **根因链**：后端所有卡片变更 WS 广播（card_update/card_create/card_delete）都 `exclude=username` → 操作者本人收不到自己的广播 → 本机统计卡刷新完全靠本地显式 `renderProgress()` → 而 `toggleCardDone`（勾选完成）和 `setCardStatus`（弹窗头部状态按钮）只 reload 不刷统计。新建/编辑/删除/复制/导入路径本来就调了，所以「改状态不更新、新建反而更新」
- 修复：两条漏刷路径补 `renderProgress()`；`renderProgress` 加请求序号守卫 `_ovSeq`（快速连续变更时并发响应乱序回落，旧响应 seq 不一致直接丢弃，防旧数据盖新数据）
- 关键认知：**广播 exclude 本人 = 本机 UI 一切必须本地显式刷**，新加变更入口时若只 reload 记得想统计带；子事项状态不参与 /api/overview 口径（WHERE parent_id=''），无需刷
- 实测：ops/test_d119_stat_refresh.py CDP 7/7（勾选→已完成±1、弹窗改进行中+1、改回还原、window.__t 全程未变=零刷新）

## #133 修复发布回滚.bat 换行符损坏（#132 编辑引入，root 仓提交 cc57a1d）

- **修复**：二进制读 → 统一 \r\n → GBK 写回（156 行 CRLF）；实测菜单完整渲染、Q 正常退出
- **bat 编辑铁律（升级版）**：编辑 bat 必须二进制读写（open(p,'rb')/open(p,'wb')），保 CRLF + 原编码；文本模式读写哪怕 newline='' 也会毁换行。#132 只记了「GBK 编码」教训、没实测 bat 本体就提交 → 这次事故。以后改完 bat 必须跑一次 cmd 实测
