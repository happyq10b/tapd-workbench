### 关键设计决策
1. **子事项弹窗复用主事项弹窗（editModal）**，不新建弹窗。
   - `EDIT_IS_SUB` 标志位；子事项模式隐藏「所属看板」「参与人」，补「父事项」信息区 + 父时间范围 min/max 约束
   - 子事项保存**不发 cc**、**不跨看板移动**（否则会带上一次主事项的残留值）
2. **抽取共享渲染基元**（消除三处重复实现）：
   - `statusCls/statusText/statusTag()` — 状态标签
   - `statusOptions()` — 状态下拉选项
   - `pinBtn()` / `doneBtn()` — 置顶/完成情况文字按钮
3. **删除抽屉内重复的子事项编辑面板**（renderDrawerEdit / renderSeTodos / addDrawerTodo /

   编辑统一走共享子事项弹窗。DRAWER_STACK 的 'edit' 类型已移除。
4. **子事项就地刷新**：`patchSubTreeNode()` + `refreshDrawerIfOpen()` ——
   改状态/置顶后只重绘目录与抽屉，**不整页 reload**（reload 会把已展开的子事项目录折叠掉）。

### 踩坑
- **`resetDrawerNewForm()` 必须同时清 `DRAWER_OWNER` 数组并 `initPersonPicker('dn_owner', ...)` 重绑**，
  只清数组不重绑，界面上的已选成员标签仍留着。
- **`select.innerHTML = statusOptions(...)` 后还要显式 `select.value = cur`**，
  否则某些情况下 select.value 取不到选中值。
- vm 测试里 `let ME` / `let TEAM_MEMBERS` 是**词法绑定**，外部 `sandbox.ME = {...}` 赋值无效，
  必须用 `vm.runInContext('ME=...')`；`var` 声明的（DRAWER_OWNER/DRAWER_STACK）才能直接赋值。

### 后端
- `GET /api/cards/{id}/children` 排序改为「置顶优先 + 创建时间降序」（原来是最旧在前），
  与主事项列表 `cmpCard` 对齐。

- **本地 app 只路由 `/` 和 `/login`，不挂载静态目录** → 自造的验证页放不进 src/static/。
  解决办法：把验证页放到临时目录，用 `python -m http.server 8199` 单独托管
  （CSS 已内联，不依赖 app）。
- **窄屏验证用 iframe**：`@media` 断点按 iframe 自身视口宽度生效，
  外层 harness 的 `.frame` 必须写 `flex:0 0 auto`，否则 iframe 被 flex 压缩、断点不生效。
- Windows 下 Python 不认 Git Bash 的 `/tmp`，要用 `C:/Users/admin/AppData/Local/Temp/...`。
- 杀临时服务前先用 `netstat -ano` 按端口定位 + `wmic ... get CommandLine` 核对命令行，
  避免误杀 8100 的本地开发服务（两者父进程不同）。

## 2026-10-28 17:58 · 同步开关.bat 菜单中文化（GBK 编码坑）

**需求**：把 `同步开关.bat` 菜单里 1-4 后面的英文说明改成中文。

**关键约束（踩过才知道）**：
- cmd 本机代码页 = **936（GBK）**。`.bat` 里带中文必须以 **GBK 编码**写回，
  用 Edit/Write 工具（默认 UTF-8）写会变成乱码。
- 但 **不能用 `chcp 65001` 绕过**！脚本里 `PYTHONIOENCODING=gbk` + iconv 转 GBK，
  改代码页会让 verify.py 的输出（GBK 字节）被 65001 解释 → 验证阶段反而乱码。
- `.gitattributes` **早已写好**约定：`*.bat binary`（GBK + CRLF，禁止任何转换）。
  所以 git 把它当二进制、`git diff` 显示 `Bin 6150 -> 6143` 是**设计如此**，不是出了问题。
  `git check-attr` 显示 `text: unset` → 不会被行尾转换弄坏。

**做法**：python 脚本读 `gbk` → 按行号替换（不用字符串匹配，避免空白猜错）→
按**显示宽度**（CJK 算 2 列）补空格对齐到第 29 列 → `encode('gbk')` 写回，保留 CRLF。

**验证**：逐行 diff 确认只改了 83-86 四行、219 行数不变、CRLF 218 处不变；
再实机 `cmd //c "同步开关.bat"` 喂入 `4`，把输出按 GBK 解码，确认中文正常渲染、
列对齐未偏移、正常进入 Cancelled 分支。

**提交**：顶层仓库 `13af66d`。未跟踪的 `工作转移手册.md` 与 memory 文件按惯例**没动**。

### 🔴 根因：cmd 的 echo 与 Python 的 stdout 走的不是同一条路
- **cmd 的 `echo`**：读 .bat（GBK）→ 转 Unicode → `WriteConsoleW` → **与代码页无关，永远正确**
- **Python 的 stdout**：裸字节 write → 控制台按**输出代码页**解释 → **完全依赖代码页**

所以终端若是 UTF-8(65001)：菜单正常（走 Unicode API），但 Python 的 GBK 字节
被当 UTF-8 解释 → `═`(A854) 变成 `�T`、`✓`(U+2713) GBK 编不出 → `?`。

**修复（提交 79fa972）**：
1. `同步开关.bat` 开头 `chcp 936` 强制统一，8 个退出点前 `call :restore_cp` 还原原代码页。
   理由：三者编码必须一致 —— .bat 源文件 GBK / Python 输出 GBK / bash 输出经 iconv 转 GBK。
2. `verify.py` `sync.sh` 的 `✓ ✗` → `√ ×`（GBK A1CC / A1C1），否则 GBK 模式下变 `?`
   或被 `iconv -c` 直接丢弃（sync.sh 的 ✓ 一直是被丢掉的）。

**验证方式（可复用）**：`cmd //c "chcp 65001 > nul & 同步开关.bat"` 强制 65001 复现用户环境，
再把捕获字节按 GBK 解码比对。改完两种环境输出字节完全一致、GBK 解码干净。

### 🟡 坑：sync.sh 的 normalize_lf 会弄脏 src 工作区
`sync.sh` 传输前把 `src/app/*.py`、`src/static/*.html` 的 CRLF 就地转 LF。
老文件是 CRLF，转完 git 认为工作区被改（`git status` 显示 M 但 `git diff` **为空**——
索引 blob 与 HEAD blob 完全相同，纯粹是 stat 缓存没跟上）。
**解法**：`git checkout -- static/index.html` 刷新（内容本就不变，字节还是 LF）。
`src/.gitattributes` 已有 `*.html text eol=lf`，所以这是一次性历史遗留，之后不再复现。

### 🟡 指纹会因行尾变化而变
`code_fingerprint()` 只哈希 src/app + src/static + requirements.txt + manage_users.py，
**不含 ops/**。CRLF→LF 归一化让指纹从 `fd94cdfe…` 变成 `db1d9e14…`（服务器拿到的是 LF 版，
与本地一致 ✓）。改 ops/ 不会影响指纹，但改 src/ 一定会。

### 🔴 重要发现：dev 与 prod 的真实差别
```

prod: uvicorn app.app:app --host 0.0.0.0 --port 8000 --proxy-headers --forwarded-allow-ips='*'
```
**唯一差别是 prod 多了 `--proxy-headers`** → dev 模式下 uvicorn 不信任 nginx 传来的
X-Forwarded-For，**应用侧看到的客户端 IP 全是 127.0.0.1**（登录日志/审计失真）。
