## 📌 一页纸速览

**定位**：不是再做一个系统，是给已经跑起来的平台装上**管理属性**——从"事项记录工具"升级为"财务中心的管理抓手"。

**现状矛盾**：数据已经收上来了（7 看板 / 263 板块 / 1263 事项 / 12 架构节点 / 7 级权限内核 / 8437 条审计），但**管理动作仍发生在平台之外**（微信群、Excel、邮件）。

**四个优势**
1. 贴合财务中心架构，权限框架契合管理需求 —— 7 级角色 + 4 层资源 + fail-closed + 实时判定，权限写进数据模型，搭一次架构全平台跟着变
2. 基于用户习惯灵活搭建 —— 四层对象可复制、板块自带"日常/专项"属性、26 列单一数据源导出、筛选候选自带权限过滤
3. 化零为整收束日常事务 —— 管理从"追人"变成"看板自带"
4. 可脱离 AI 独立使用 —— 前四模块纯手工可用，AI 只在第五模块，服务器可纳入公司管控

**五大功能**

| # | 功能 | 建设性质 | 关键增量 |
|---|---|---|---|
| 1 | 工作事项登记台（我的 / 本部门 / 跨部门三视角） | 视图层增强 | 加聚合入口，数据模型不动 |
| 2 | 各部门主页（内容模块化配置） | 能力扩展 | 容器已有，内容与配置层待建 |
| 3 | 重大财务事项汇总（台账 + 逐条授权） | 新建 | 表不存在，全新建设 |
| 4 | 标杆评优平台（提名→投票→统计→公示→归档） | 新建 | 展示层已有，前半程全无 |
| 5 | 智能总结（MCP 只读取数 → Agent 出初稿 → 人工校对） | 新建（AI 集成） | 部署方案已有，未实施 |

**实施路径**：P0 数据体检 → P1 登记台 → P2 重大台账 → P3 评优平台 → P4 部门主页 → P5 智能总结
（每阶段独立产生管理价值，不追求一次做完）

**需中心支持的三件事**：① 评优规则与时间表拍板；② 四个零看板部门的归属口径；③ 向信息部申请内网服务器资源。
