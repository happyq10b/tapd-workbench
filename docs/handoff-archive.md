# 交接记录归档 · 指引页（v1 机制遗留）

> **本文件是 v1 归档机制留下的入口，现已改为指引页。**
>
> 归档区实体位置已迁移到 → **`docs/handoff/`**
> - 全量索引：`docs/handoff/INDEX.md`
> - 归档正文：`docs/handoff/records/R00NN-<标题>.md`（一期一文件）
>
> **保留本文件不删**，是为了让历史引用（记录 #6 等）不断链。

---

## 为什么迁移

v1 机制把归档正文堆在一个大文件里（就是本文件），有三个问题：

1. **排障要读大文件** —— 为找一条记录得 grep/读整个文件，违反渐进式披露；
2. **归档是长距离编辑** —— 从大文件中间删一段，最容易踩本项目最忌讳的
   "并行 Edit 同一文件 5 次全返回成功、实际 0 改动"（见 `工作转移手册.md` §2.3）；
3. **阈值形同虚设** —— v1 写"记录数 > 12 条移出"，实际已 16 条仍未执行，
   说明**光有阈值没有人执行 = 没有归档**。

改成「一条记录一个文件」后，归档动作变成"**新建文件 + 删一段**"，
风险显著下降；配合 `docs/handoff/INDEX.md` 的全量索引，历史依然一条不丢。
