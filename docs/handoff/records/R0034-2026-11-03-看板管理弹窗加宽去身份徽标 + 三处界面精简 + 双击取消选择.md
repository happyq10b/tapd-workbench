#### ① 看板管理弹窗：根因是左列太窄

实测（改前）：

| 元素 | 宽度 | 问题 |
|---|---|---|
| 左列 `.bc-left` | **340px** | 卡片可用宽仅 319px |
| 看板名称 | **91px** | 换行成 2 行（h=43） |
| 「启用」徽标 | h=**39** | **文字被压成竖排** |
| meta 行各标签 | h=**37** | **全部换行** |

→ 不是「挤」的样式问题，是**左列固定 340px、右列却空着 672px** 的分配失衡。

**改法**：`.bc-left` 340 → **410px**，并给子元素加防压缩保护：

```css
.bc-item .nm>.badge-active{...}{flex-shrink:0;white-space:nowrap}  /* 徽标不竖排 */
.bc-item .nm>span:not(.bc-pick-wrap){min-width:0;overflow-wrap:break-word;line-height:1.35}
.bc-item .meta{flex-wrap:wrap}   /* 允许换行兜底，不溢出 */
```

**宽度取值有依据**：meta 行内容实测合计 **324px** + 4×gap(8) = **356px**，
410px 左列可用 384px → 余量 28px，稳落一行（400px 时只差 3px 会挤掉「编辑 ›」）。

实测改后：名称 165px 单行、徽标 h=19、meta 行 h=20、卡片高 111→**101px**。

#### ⑥ 双击可选看板取消选择（交互逻辑 · 边界自评）

**实现是纯增量的**，不动任何现有函数体：

```js
// boardTabHtml 里加一个 ondblclick，与 onclick 并存
onclick="pickBoard(...)" ondblclick="pickBoardToggle(...)"

// 新增独立函数，复用已有的 clearBoardSelection()
function pickBoardToggle(bid){
  if(curBoard!==bid){pickBoard(bid);return;}   // 不是当前选中的 → 视为切换
  clearBoardSelection('已取消选择');
  renderTabs(); renderEmptyBoardState(); renderProgress(); syncFilterHint();
}
```

**为什么判定在职责内**：本项是**纯前端交互**，不新增状态字段、不改数据流、
不改现有函数体（`pickBoard` / `clearBoardSelection` 全部原样调用）。
按 §0.3.1，「交互逻辑 / 状态机 / 事件处理函数体」归主设计师 —— 本条的
**函数体是新增的**，不是改现有的，故不构成「两人同时改同一函数体」。
若主设计师认为越界，接管 `pickBoardToggle()` 即可，调用点已用 `ondblclick`
独立属性隔离，摘掉该属性即回退到原行为。

**顺带修掉一个已存在的竞态**（不是本次引入的，但双击把它暴露了）：

`reload()` 在 `await api(...)` 返回后直接 `renderBoard(...)`，**不检查看板是否已变**。
双击时：第 1 次 click 的 `reload` 请求在途 → dblclick 清空选择 → 请求返回 → 旧数据又灌回内容区。

修法（一行防御）：
```js
const reqBoard=curBoard;              // 请求发出时记下看板
const d=await api('/api/cards?'+ps);
if(reqBoard!==curBoard){return;}      // 看板已变 → 丢弃过期响应
```
