**`OWNER_NONE` 语义边界的最终结论**（T-001 唯一未决项，已从「待业务方确认」转为已定）：

- 架构树回填时，哨兵值以**裸值 `__no_owner__`** 放进 `TREE_PICK.selected`，
  **不加 `__P__` 前缀** —— 它不是架构里的真实人员，加了前缀永远匹配不上（`okSel` 虽放行，
  但树内没有这个条目）；「勾选 / 确定时**保留**它」这条不变。
- 后端 `person=__no_owner__` 走 `want_none` 分支（owner 为空或纯空白），语义未变。
- **实测**（真实 Chrome + CDP）：预置 `PERSON_SEL={__no_owner__, 吴婷婷}` → 开树 →
  `selected=['__no_owner__','__P__吴婷婷']`、`noneOwner=true`、`.tp-none-node` 可见、
  `#tp_opt_none` 勾选态正确 → 直接「确定」→ 回传 `['吴婷婷','__no_owner__']`、
  chips 回显「吴婷婷 × 无负责人 ×」。**往返一致，无丢失、无重复。**
