**注意事项与约束**

- 🔴 **我此前对 `.workbuddy/memory/` 的判断有误**：一直以为它被 `.gitignore` 覆盖，
  实际 `git check-ignore` 返回未忽略、`git ls-files` 显示**它一直是 git 追踪的**，
  且历来每个 Agent 提交时都把自己的日志段落一并提交（查提交历史：
  `992fb4e`/`1b8c822`/`50b5fff`/`6ea842c`/`9c323ee` 都含该文件）。
  → **教训：判断文件是否入库，用 `git ls-files` / `git check-ignore` 实测，别凭印象。**
- 🔴 **日志是多 Agent 交错写入的**：`UI设计师`（09:00→11:43）与 `主设计师`
  （09:40→10:50）在**同一份文件**里按时间穿插写段落。
  → 因此规矩里明确：**只追加自己的段落**、不动他人段落的顺序、
  写完回读确认他人段落没丢、**提交时若发现他人段落有未提交改动要一并提交**（否则会覆盖）。
- 💡 **两处都要写，分工不同**：
  **日志** = 当天流水（细，含过程与踩坑）；**HANDOFF** = 跨 agent 正式交接（粗，含约束与待办）。
  只写日志 → 别人不去翻；只写 HANDOFF → 过程随归档丢失。
