**类型**：流程建设 —— **界面零改动、逻辑零改动**（只动 `HANDOFF.md`）

**做了什么**

用户明确「你是主设计师、拥有全部职能，但专业的事要交给专业的 Agent」，
而项目里已有专职的 `UI设计师`。**光有台账不够 —— 缺一条可执行的派工判据**，
否则「派工」会退化成两个 Agent 凭感觉互相推诿。所以把边界写死进 §0.3.1：

1. **按「活的内容」分类，不按「谁先动手」分类** —— 七行判据表：
   - 配色/字号/间距/圆角/阴影/动画/断点/无障碍属性 → **UI设计师**
   - 视觉层 HTML 结构（语义标签、`aria-*`、纯展示容器）→ **UI设计师**
   - 交互逻辑 / 状态机 / 事件处理函数体 / 字段集合 → **主设计师**
   - 后端接口 / 数据结构 / 权限 / 鉴权 → **主设计师**
   - 运维脚本 / 部署 / 同步 / 门禁 → **主设计师**
   - 需求拆解 / 技术方案 / 派工 / 验收 / 与用户拍板 → **主设计师**（唯一对用户出口）
2. **「分文件不分行」原则** —— 同一次需求里 UI 与逻辑常常缠在一起
   （例：新增一个筛选项 = 加控件 + 改状态 + 加接口参数）。
   规矩是 CSS/样式段归 UI设计师、JS 逻辑段归主设计师，
   **同一个函数体不要两个人同时改**；真分不开时，
   由主设计师先改逻辑、再把「具体要什么样式」写成明确条目派给 UI设计师。
3. **交接路径闭环** —— 主设计师把 UI 活写进 §五 并指名 `UI设计师`，
   UI设计师 认领改 🔄 → 做完标 ✅ 并附署名与关联记录号。**署名天然不冲突**（两个固定署名）。

**注意事项与约束**

- 💡 **「分文件不分行」是本条最关键的一句**。CSS 与 JS 常常在同一文件里，
  按行分是伪边界（同文件并行 Edit 极易互相覆盖），
  按**职责段**分才可执行：样式段整体归 UI设计师、逻辑段整体归主设计师。
- ⚠️ **主设计师拥有全部职能 ≠ 主设计师什么都自己干**。
  §0.3.1 的存在就是为了给「不自己干」一个**有依据的、可交接的**出口，
  而不是让 UI设计师 觉得被抢活、或主设计师觉得被束缚。
- ⚠️ **派工条目必须写清「要什么样式」到可执行的粒度**
  （类名、样式值、影响范围），否则 UI设计师 得回头问，等于没派。
- 本条**未验证代码**（无代码改动）→ 不需要跑门禁；`ops/verify.py` 在 #7 已 7/7。
