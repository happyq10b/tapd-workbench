# 归档正文区（L3 正文层）

> **本目录存放已从 `HANDOFF.md`「七、详细记录」移出的历史记录，一期一文件。**
>
> 目的：让 `HANDOFF.md` 保持可读 —— 详细记录是流水账，只会越来越长，
> 每次开工都通读的成本随项目线性上升，最后的结果就是**没人读**。
>
> 维护者：**交接管家**。执行 Agent **不直接往这里放文件** ——
> 归档由管家统一执行（写文件 → 登记索引 → 删正文 → 回填批次 → 回读校验）。

---

## 一、查找入口

```
docs/handoff/INDEX.md            ← 全量目录，每条一行 + 本目录下的正文路径
        ↓
docs/handoff/records/R00NN-<标题>.md
```

> 排障时**只读一篇**。不要把本目录整个 Read 进来 —— 一次只取你要的那一条。

---

## 二、文件命名规范

```
R{序号4位}-{日期}-{标题}.md

例：R0015-2026-11-02-闭环 T-005 窄屏 4px 缺口.md
```

| 规则 | 说明 |
|---|---|
| **序号 4 位补零** | 必须能排序：`R0001 < R0002 < R0010`。序号与记录序号一致 |
| **日期** | `YYYY-MM-DD`，取该记录的日期 |
| **标题** | 取记录标题；**空格保留**，Windows 非法字符（`: * ? " < > \| / \`）替换为 `-`；**截断 40 字** |
| **署名不进文件名** | 署名在索引表与正文首行，避免中文长文件名 |

## 三、归档正文模板

```markdown
# R0017 · 2026-11-02 · 交接管家 · 标题

> 归档自 `HANDOFF.md`「七、详细记录」，归档批次：第 N 批（YYYY-MM-DD）
> 原记录编号 #17 · **本文件是历史快照，不再修订** —— 要改结论请改权威章节，
> 再由管家更新 `HANDOFF.md`「★ 当前状态摘要」。

（原正文原样搬运：类型 / 做了什么 / 涉及文件 / 注意事项与约束 / 遗留待确认）
```

> ⚠️ **归档只搬运，不润色、不重写、不修正历史笔误。**
> 历史条目里过时的地方（例如章节号已后移）保留原文，**就地加括注**指向现位置 ——
> 这是本项目一贯的「不重写历史」原则。
