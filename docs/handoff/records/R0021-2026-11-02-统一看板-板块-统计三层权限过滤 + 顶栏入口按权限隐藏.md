#### ① 根因：板块级权限没有下推到所有统计点

先建夹具实测（一个看板 × 3 板块 × 2 事项；4 个角色账号），逐接口核对：

| 检查项 | 改前 | 结论 |
|---|---|---|
| `/api/cards` 的板块列表 | ✅ 走 `visible_columns` | 正确 |
| `/api/cards` 的 `total` / 板块计数 | ✅ 基于已过滤的 `mine` | 正确 |
| `/api/overview` 的统计 | ✅ `filter_rows` | 正确 |
| `/api/boards/{id}/columns` 的可见板块 | ✅ `visible_columns` | 正确 |
| **`/api/boards` 的 `card_count`** | ❌ **直接 GROUP BY 统计 cards 表** | **只做了看板级过滤** |
| **`/api/boards` 的 `col_years`** | ❌ 同上，全量板块的年份 | 泄露越权板块的年份 |
| **`/api/boards/{id}/columns` 的 `counts`** | ❌ 全量计数（越权板块的数随响应下发） | 数据出服务端 |

**实测证据**（`__pv_col1`：只授权 COL_1，其余板块无权）：

```
/api/boards 的 card_count = 6      ← 错！用户实际只能看到 2 条
/api/cards 的 total        = 2      ← 对
可见板块                   = ['板块一'] ← 对
```

即：**看板级权限生效了，板块级权限没跟上** —— 用户在「看板管理」里看到的卡片数
比实际能看到的条数多 3 倍。

**修法**（`src/app/app.py`）：

```python
# /api/boards
counts = defaultdict(int)
for r in filter_rows(dbq('SELECT board_id, column_id FROM cards WHERE deleted=0'),
                      visible, cols_perm):      # ← 走两级权限
    counts[r['board_id']] += 1
col_years = defaultdict(set)
for r in visible_columns(username, visible, cols_perm):   # ← 按可见板块算年份
    if r.get('year'):
        col_years[r['board_id']].add(r['year'])

# /api/boards/{id}/columns
for r in filter_rows(dbq("SELECT board_id, column_id, column_name, status FROM cards"
                         " WHERE deleted=0 AND board_id=?", (board_id,)), boards, columns):
    ...
```

**统一口径**：三处统计（`/api/cards`、`/api/overview`、`/api/boards`）现在**全部**
基于 `filter_rows` / `visible_columns` —— 同一权限主体在各处的可见范围完全一致。

#### ② 顶栏入口按权限隐藏（用户明确要求）

新增 `applyPermissionUI()`，把散落在 `init()` 里的权限判断集中一处，
**显示条件 = 后端接口的权限要求**（没有权限就别显示，免得点进去撞 403）：

| 入口 | 后端接口 | 要求 | 处理 |
|---|---|---|---|
| 成员与账号管理 | `/api/users*` | require_admin | 非管理员隐藏 |
| 架构管理 | `/api/org*` | require_admin | 非管理员隐藏 |
| **看板管理** | `/api/board-config`(写) `/api/boards`(建) | require_admin | **非管理员隐藏**（用户补充要求） |
| 操作日志 | `/api/audit` | require_admin | 非管理员隐藏 |
| 新建板块 | `POST /api/columns` | require_editor | 只读隐藏 |
| **更多 › 恢复**（JSON 导入） | `POST /api/import` | require_editor | **只读隐藏** |
| **更多 › 导入**（xlsx） | `POST /api/import/xlsx` | require_editor | **只读隐藏** |
| 更多 › 备份 / 模板 / 导出 | `GET /api/export` `/api/import/template` `/api/export/xlsx` | require_auth | **保留**（只读也能用） |

「恢复」原来没有 `id` → 补 `id="jsonImportBtn"` 才能按权限隐藏。

**注意事项与约束**

- 🔴 **改任何统计前先问「口径跟谁一致」**。本项目的**唯一权威口径**是
  `filter_rows(rows, boards, columns)`（看板级 + 板块级两级权限）。
  凡是绕开它直接查 cards 表做统计的，都有漏权限的风险 ——
  本次 `/api/boards` 就是这样漏的。
- 🔴 **`visible_columns` 是板块可见性的唯一出口**。板块列表、板块年份都该走它，
  不要另写一份过滤逻辑 —— 容易漏字段（如 `column_id` vs `column_name`）。
- ⚠️ **`dbq` 带 `?` 占位符必须传 params**，否则运行时报
  `Incorrect number of bindings supplied`（本轮踩了两次）。
  且本地服务**不用 uvicorn --reload**（Windows 上会卡死），
  改后端代码要等 watchdog 自动重启，否则测的还是旧代码 —— 本轮因此误判过一次。
- 💡 **`applyPermissionUI()` 集中管理**优于散落在 `init()`：
  权限矩阵写进注释里的表格，后人加新入口时能照着填。
- ⚠️ **测试夹具会污染真实库**：本轮建了 `__pv_` 前缀的临时账号/看板做实测，
  导致 `ui_check_tree.py` 的「树上人员仍 39 人」断言失败（期望 36）——
  **不是代码问题，是数据污染**。已清理（boards 8→7）。
  → 教训：临时数据要么 `try/finally` 清理，要么断言用**相对值**不用绝对值。
  本轮新增的两个测试均已用 `try/finally` + 前缀隔离。
