**注意事项与约束**

- 🔴 **需求 5 踩了一个隐蔽的坑，值得记住**：
  `html{min-width:1200px}` 只锁住**文档宽度**，而 **CSS 媒体查询仍按「视口宽度」判定**！
  实测：视口 1000px + min-width:1200px → `@media(max-width:1180px)` **照样触发**，
  顶部栏仍变两列、板块仍变四行、筛选栏仍换行 —— **布局照样变形，min-width 形同虚设**。
  → 光加 min-width 不够，**必须同时把会影响布局的断点收敛掉**。
  → 补充：`.topbar-main` 是 `1fr` 弹性列，视口窄 → 主体被压窄 → 三列小栅格从 302px 缩到 249px。
  即形态稳住了但**尺寸仍在漂** → 追加 `.topbar-main{min-width:778px}` 才真正做到「大小位置都不变」。
- 🔴 **需求 1 的映射表依赖 DOM 序号，不依赖部门名**：
  CSS 无法按文本选中元素，`order` 只能配 `:nth-child`。
  后端 `_dept_order()` 给出的 DOM 顺序实测为 财务中心/核算部/总账部/管理部/资金部/商务部，
  故映射写作 nth-child(1)→视觉1、nth-child(6)→视觉2 …（**DOM序号 ≠ 部门名**）。
  ⚠️ **若后端部门顺序变化，本映射必须重新核对**。
  若要「按部门名排序」，需由主设计师在 JS 侧按名排序后交回 —— 属逻辑层，UI侧不越界。
- 💡 **我的测量脚本一度误报**：最初 `rowProfile` 按 DOM 顺序收集每行元素，
  导致 CSS `order` 重排后的行显示成错乱序列，**看起来像排序没生效**。
  实际布局是对的 —— 是**测量方法**错。已修正为按 x 升序。
  → 教训：**看到"不对劲"先质疑测量方法**，别急着改代码。
- ⚠️ **需求 4 的关键**：光给 `.cf-chips` 加 nowrap 不够，**`.cf-field` 本身也必须 nowrap**。
  否则 chips(104px) 与输入框(52px) 在 104px 宽的 field 里换行 → field 高 25→51px → 工具栏 61→87px。
  同时删掉了旧的两条重复定义（`.cf-field` / `.cf-input`），避免两套规则打架。
- ⚠️ **需求 3 的 HTML 包裹层不影响 JS**：核实过 `renderTabs()` 只按 id 取元素
  （`tbDepts` / `tbBoards`），**不依赖带的数量或层级** → 结构改动安全。
- ⚠️ **行尾保持 CRLF**：改动后文件仍是 7309→7401 行全 CRLF，无混合。
