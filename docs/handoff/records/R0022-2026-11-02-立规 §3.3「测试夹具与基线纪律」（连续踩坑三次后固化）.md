**回顾**：2026-11-02 一天内**同类问题犯了三次**：

| # | 时间 | 污染源 | 表现 | 误判 |
|---|---|---|---|---|
| 1 | 11:47 | `__ui_` 前缀的临时账号 + 看板 | `ui_check_tree.py`「树上人员仍 37 人」失败（期望 36） | 以为是自己刚改的权限代码坏了 |

| 3 | 15:00 | `__pm_` / `__pe_` 测试夹具 | 同上 | 同上 |

每次都要花 10~30 分钟排查「是不是自己改坏了」，**而真相只是库里多了一条临时数据**。

#### 根因（不只是手滑，是没有纪律）

**① 测试断言硬编码了全局基线数字** —— 这是**真正的设计缺陷**：

```python
ok(r.get('persons', 0) == 36, '拼音组合期间树上人员不消失（仍 %s 人）' % r.get('persons'))
```

只要库里多一条人员（新建板块、导入、任何临时夹具），这条断言就假性失败 ——
**而它与被测代码毫无关系**。

**② 一次性手动实测的夹具没有 finally 保护** —— 测试文件里的夹具都有
`try/finally: cleanup()`（4 个权限测试文件全部核查过），但我**手工跑的一次性
shell/python 脚本**造的夹具（`__ui_` / `__pv_`）不在任何测试文件里 → 没人替我清理。

#### 立规（写进必读区）

新增 **§3.3「测试夹具与基线纪律（2026-11-02 立规 · 连续踩坑三次后固化）」**，
并在「② 开工检查项」加了必读指针。内容三条：

| # | 纪律 | 落地 |
|---|---|---|
| 1 | **夹具必须自清理** | 专属前缀命名空间 + `try/finally: cleanup()`；cleanup 删全 7 张表（cards / board_columns / boards / board_config / users / team_members / org_appointments） |
| 2 | **断言不得硬编码全局基线数字** | ❌ `== 36` → ✅ `== base_total`（先实测出基线再比对） |
| 3 | **一次性实测数据测完立刻删** | 手工脚本造的夹具没有 finally 保护 → 当场删或记下待删清单 |

外加 **诊断口诀**（把「先分清谁引入的失败」固化成命令）：

```bash
git -C src stash push -q static/index.html   # 暂存自己的改动
ops/.localvenv/Scripts/python.exe ops/ui_check_tree.py   # 跑一次
git -C src stash pop -q
# 仍失败 = 不是你引入的 → 查数据；通过 = 是你引入的 → 正常排查
```

> 💡 **「失败突然出现、且失败点与你的改动毫无关系」→ 第一反应应该是数据污染，不是代码。**

#### 同时修掉了那处脆弱断言

`ops/ui_check_tree.py` 的两处 `36` 改成**实测基线**：

```python
base_total = r.get('persons', 0)      # 用例7 开头实测「无搜索词时树上总人数」
ok(r.get('persons', 0) < base_total, '搜索「吴」过滤出 %s 人（全部 %s 人）' % ...)
ok(r.get('persons', 0) == base_total, '拼音组合期间树上人员不消失（仍 %s 人，基线 %s）' % ...)
```

**并做了对抗验证**：故意往库里注入 1 个临时人员（模拟污染）→ 基线自动变成 37 →
测试 **45/45 全绿**（改之前这里必然失败）。验证后已清理。

**注意事项与约束**

- 🔴 **这条铁律的价值在于「提前知道」，不在于「记住」** —— 所以它写在
  **§三 验证流程**（改完代码跑测试前必读）**+ 开工检查项**（每次开工必看），
  而不是只写在当天的工作日志里（日志会被归档、不会再被读到）。
- ⚠️ **`base_total` 的采集位置必须在使用之前** —— 本轮改的时候先定义在用例8，
  但用例7 就要用 → 报 `NameError`。已提前到用例7 开头。改这类相对基线时注意顺序。
- ⚠️ **相对基线不是万能的**：它只能防「数据变动导致的假性失败」，
  **不能**替代「绝对基线」对回归的检测力。若某个数字**就该**是固定值
  （如「权限收窄后统计必须是 2」），那要写死 —— 但那个 2 是**夹具自己造的**，
  不受真实数据影响。**区分：夹具内的数字可写死，真实库的数字必须相对。**
- 💡 **§3.3 里列了项目用过的所有前缀**（`__ui_` `__pv_` `__pm_` `__pe_` `__ov_`
  `__pt_` `__poll_`），新人清理时不用现查。
