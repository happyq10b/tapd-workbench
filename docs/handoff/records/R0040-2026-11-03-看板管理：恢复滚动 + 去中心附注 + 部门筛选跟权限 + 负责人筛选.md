#### ① 滚轮没了 —— 根因是 JS 把 overflow 设成了 hidden

`.bc-list` 的 CSS 一直是 `overflow:hidden`，但真正让列表不能滚的是 `setBcListScroll(n)`：

```js
if(n<=7){ box.style.maxHeight='none'; box.style.overflow='hidden'; }   // ← 这里
```

**看板恰好 7 个**（截图「真实看板 7 个」）→ 走进 `n<=7` 分支 → `overflow:hidden` +
flex 高度受限 → 超出部分被裁且**无法滚动**。

**改法**：`n<=7` 分支的 `overflow` 由 `'hidden'` 改为 `'auto'`；
同时 CSS `.bc-list` 由 `overflow:hidden` 改为 `overflow-y:auto;overflow-x:hidden`（双保险）。

实测：`overflow-y=auto`，`scrollHeight=781 > clientHeight=565` → 出现滚动条 ✓

#### ② 中心节点附注去掉

`bcDeptLabel(d)` 原：`d.is_center ? d.name+'（全部看板 · 对全员展示）' : d.name`
→ 改为 `return d?d.name:'';`

理由（写进注释）：该说明只对管理员成立（普通用户看不到中心节点），
却对所有人显示在同一个下拉里 → 冗余。
（该函数还被板块编辑弹窗、看板表单的部门下拉复用，一并简化。）

#### ③ 归属部门筛选按权限显示

**现状**：看板**列表**已按 `b.can_edit` 过滤了，但部门**下拉**用的是全量 `BC_DEPTS` → 用户能看到无权限的部门。

**改法**：`renderFilters()` 里先算出「有可编辑看板的部门集合」，下拉只列这些：

```js
const allowed=new Set(BC_BOARDS.filter(b=>b.can_edit).map(b=>b.dept).filter(Boolean));
const depts=BC_DEPTS.filter(d=>allowed.has(d.name));
```

实测（造夹具跑架构负责人）：
- 受限用户下拉 = `['全部', '__nf_dept_a']` —— **无权限的部门（核算部等）不出现** ✓
- 管理员下拉 = 有权限的全部部门 ✓
- 列表条数 == 该用户可编辑看板数 ✓

#### ④ 负责人筛选（参照板块栏的人员筛选）

**口径差异（关键）**：看板的 `b.owner` 存的是**登录账号**，而组织架构树里选的是**人名**
→ 两者之间必须有「人名 → 账号」映射，该映射来自 `/api/team` 的 `account` 字段。

**而 `/api/team` 对非管理员会清空 account**（`app.py` `get_team()` 的脱敏分支）→
受限用户拿不到映射 → 树里所有人被判为「无账号」→ **一个人都不可选**（实测 clickable=0）。

**故做两级形态**（`renderOwnerFilterBtn()`）：

| 角色 | 控件 | 说明 |
|---|---|---|
| 管理员等（有映射） | **树弹窗按钮**（参照板块栏人员筛选） | 显示姓名，可选「无负责人」 |
| 受限用户（无映射） | **下拉降级**，选项 = 可见看板的 owner 账号 | 筛选逻辑是**纯前端过滤**（比对 `b.owner`），**不需要映射也能筛**，只是显示账号而非姓名 |

- 后端一旦放开 account（T-011）→ **自动切回树弹窗**，前端无需再改。
- 无映射时点树弹窗 → 给明确提示「当前权限下无法按姓名选负责人，请使用下拉筛选」，
  **不弹一个一个人都不能选的空树**。

实测（管理员）：树面板 48 节点 → 勾选「余河」→ 按钮文字变「余河」+ 高亮 → 列表过滤生效 ✓
实测（受限用户）：降级下拉选项 `['全部', '无负责人', owner 账号]` → 选中后列表过滤生效 ✓
