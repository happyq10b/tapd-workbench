**注意事项与约束**

- 🔴 **行高未受影响（已实测，这是本条最需要盯的风险）**：
  事项行高 **47px 不变**，字段列起点 `[456, 632, 760, 916]` **跨 6 行完全一致**，
  `.fcols` 宽 648px、`.slot-pin` 宽 84px —— §二 C-1~C-3 标定值**全部保持**。
  → 行内按钮加高到 25px < 原行内容高度，故行高纹丝不动。
- 🔴 **「逾期」标签原用行内 `style="color:var(--danger)"`** —— 行内样式优先级最高，
  会压掉 CSS 里的深色字（实测对比度仍 3.42）。
  → 已改为独立类 `.lock-tag-overdue`；「已暂停」同理改为 `.lock-tag-paused`。
  **教训：改 CSS 颜色前要先查有没有行内样式在压着。**
- 💡 **对比度选色不能拍脑袋**：先算了 AntD 标准文字色阶（`#389e0d`/`#d46b08`/`#8c8c8c`），
  发现**它们也不达标**（3.22~3.56）—— AntD 本身未按 WCAG AA 设计。
  → 最终用「同色相 + 逐档搜索首个达标值」算出上表 9 个色值。
- 🔴 **扫描器自身有两处方法学缺陷（已修）**，否则会把"改好了"报成"没改好"：
  ① `Array.prototype.forEach.call(arr, 0, 80)` 的第三参是 **thisArg** 不是「取前 80 个」
     → 传 0 使回调**静默不执行** → 焦点统计恒为 0（误以为修复无效）。
  ② `:focus-visible` **只对键盘导航激活**，程序化 `el.focus()` 不触发
     → 原实现把所有元素都误判为「无焦点环」。
     → 改为**扫描样式表**判断规则覆盖关系，不依赖运行时 focus。
  另修正两处误报排除：纯文本 span（`.item-title` 宽 270px 但高 22px，是行内文字非点击目标）、
  已用 `::after` 扩热区的指针图形。
  → **这意味着「491→0」不等于纯靠 CSS 改出来的**，约 340 项属误报。
- ⚠️ **删除了 `.add-item-btn` 的重复定义**（新定义在前、旧的在后，会打架）。
- ⚠️ **部门带高度 115→123px**（`.dept-home` 加高所致）—— 属预期，部门卡是独立容器，不涉字段列。
