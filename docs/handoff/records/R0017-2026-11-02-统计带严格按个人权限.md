**类型**：后端（权限过滤）—— **UI 样式零改动**

**做了什么**

用户要求「页面上的三个统计必须根据个人权限来，权限以外的不要统计」。
先做**全面排查**，确认统计本身的权限隔离是好的，再定位到真正的漏洞。

#### 排查结论：统计数字本身是对的，漏的是「部门清单」

| 检查项 | 结论 |
|---|---|
| `/api/overview` 的权限链 | ✅ `user_allowed()` → `filter_rows()` → `perm_pass()` 两级过滤完备 |
| 板块级权限（`allowed_columns`） | ✅ 生效 |
| 越权传 `board_id` | ✅ 返回 0，不泄露 |
| `board_id` 空串 | ✅ 不过滤（保持既有语义） |
| 部门主页统计（`/api/dept/{dept}/page`） | ✅ `perm_pass` + `dept_boards` 双重收窄 |
| **`/api/me` 的 `depts` 部门清单** | ❌ **不按权限过滤** ← 漏洞 |

**漏洞细节**：`/api/me` 原先返回 `'depts': _dept_order()` ——
**架构里的全部部门**，与该账号的可见范围无关。
后果：普通用户的目录树会列出**自己无权访问的部门**（显示成「管理部 0」），
既暴露无权部门的组织信息，又让用户以为那里有事、点进去却是空的。

**实测证据**（建了一个只任命到「核算部」的账号 + 一个归属「管理部」的测试看板）：

| 账号 | 可见板块 | 页面统计 | 目录树部门 |
|---|---|---|---|
| admin | 8 | 总事项 1139 | 财务中心/商务部/核算部/资金部/总账部/**管理部** |
| 受限账号 | 7 | 总事项 **1136** | 核算部/管理部/资金部/总账部/**管理部** ← 多出 4 个无权部门 |

改前：受限账号统计 1136（**正确**，不含权限外的 3 条），
但目录树里赫然列着「管理部」—— 用户看到的仍是"权限外的东西"。

#### 修法

```python
# /api/me
if boards is None:
    dept_list = _dept_order()          # 管理员（boards=None=全部）→ 全部部门
else:
    seen = {item.get('dept') for item in boards_out if item.get('dept')}
    dept_list = [d for d in _dept_order() if d in seen]
...
'depts': dept_list
```

语义：**看不到的部门就不出现** —— 与 `/api/cards` 的可见范围严格一致。
管理员不受影响（`boards=None` = 全部权限）。

**注意事项与约束**

- 🔴 **`/api/me` 的 `depts` 与 `boards` 现在必须口径一致**：
  `depts` ⊇ `{b.dept | b ∈ boards}`。改 `depts` 时别忘了同步 —— 否则目录树会出现
  有板块却没列出的部门（或反之）。
- ⚠️ **`_dept_options()`（看板管理的部门下拉）保持不变** ——
  那是管理员配置看板归属用的，理应看到全部部门。**别误改。**
- 💡 **admin 的判定是 `boards is None`**（`user_allowed` 对 admin 直接返回
  `(None, None)`）→ 不走过滤分支。改动时若换成 `if is_admin(username)`
  也能work，但**用 `boards is None` 与既有权限链口径一致**，推荐保持。
- ⚠️ **本次排查的方法值得复用**：
  用户说"统计没按权限"时，先**逐项验证统计本身**（列一张检查表），
  确认数字对不对，再去找**别的泄露路径**（这里是部门清单）。
  → 差点直接去改统计逻辑，而那本来就是对的。
- ⚠️ **测试数据会污染真实库**：本轮建了 `__ui_` 前缀的临时账号/看板做实测，
  导致 `ui_check_tree.py` 的「树上人员仍 37 人」断言失败（期望 36）。
  **已清理**（boards 8→7）。→ 教训：临时数据要么用 `try/finally` 清理，
  要么在断言里用**相对值**而非绝对值。
