**做了什么**

用户提了 3 个问题（截图：选中「总账部」后仍残留核算部的板块内容）。
定位后确认：**三者是同一个根因的三种表现** —— 板块状态（`curBoard`）与
渲染内容之间**没有联动关系**，切部门只改了目录树的展开态。

#### 根因（三处症状，同源）

| 症状 | 根因 |
|---|---|
| ① 切换不彻底（残留上个板块内容） | `toggleDept()` **只改 `DEPT_OPEN` 展开态 + `renderTabs()`**，<br>**完全不碰 `curBoard`、不重载数据** → 列表内容还是上一个板块的 |
| ② 无空状态 | `reload()` 在 `curBoard` 非空时直接拉数据；<br>空状态只有一句笼统的「没有符合条件的工作事项」 |
| ③ 初始就满屏数据 | `ensureInitialSelection()` **自动选中第一个板块** →<br>用户还没选就已经渲染了数据 |

外加一个隐藏问题：**统计带不联动**。`/api/overview` 返回的是**全局汇总**
（接口其实已经返回了 `boards` 分板块明细，但前端只用了 `ov.total`）→
切到别的板块，数字却还是全局的。

#### 改法

**① 切换彻底联动** —— `toggleDept()` 改为驱动板块状态：

```js
function toggleDept(name){
  const wasOpen=!!DEPT_OPEN[name];
  if(wasOpen){
    delete DEPT_OPEN[name]; saveDeptOpen();
    // 收起部门 → 该部门的板块不再可见 → 当前板块作废
    if(!boardBelongsToOpenDept())clearBoardSelection('部门已收起');
  }else{
    expandOnly(name);
    selectDeptBoards(name);      // 切到新部门的板块（无板块则置空）
  }
  renderTabs();
  if(curBoard)reload(1); else renderEmptyBoardState();
  renderProgress();              // 统计带同步刷新
}
```

新增三个辅助函数：
- `boardBelongsToOpenDept()` —— 当前已选板块是否仍属于「展开中」的部门
- `selectDeptBoards(name)` —— 切部门时的板块状态处理
- `clearBoardSelection(reason)` —— 清空 `curBoard` + `curYears`，带空状态原因

**② 空状态** —— 三种情形分别给明确文案（不再留白/占位）：

| 情形 | 文案 |
|---|---|
| 初始 / 未选板块 | **请选择板块** |
| 该部门无板块 | **该板块暂无数据** |
| 部门已收起 | 部门已收起，请从上方选择板块 |
| 板块存在但被筛选条件过滤空 | 没有符合条件的工作事项（保留原语义） |

**③ 初始状态** —— `ensureInitialSelection()` **只展开部门、不选板块**，
内容区默认为空；`reload()` 在 `curBoard` 为空时**直接渲染空状态、不发请求**
（否则会把全部可见板块的事项一次性灌进来）。

**④ 统计带联动** —— 后端 `/api/overview` 加可选 `board_id` 参数
（空串 = 不按板块过滤，**保持既有语义不变**）；前端 `renderProgress()`
按当前板块传参：

```js
const ov=await api('/api/overview'+(curBoard?('?board_id='+encodeURIComponent(curBoard)):''));
```

**注意事项与约束**

- 🔴 **「切板块不残留」的关键是 `curBoard` 必须是唯一真相源**。
  不能靠"隐藏旧内容"蒙混 —— 必须 `curBoard=''` + 重新渲染空状态，
  否则 WebSocket 推送（`reload(curPage)`）到达时会把旧内容又灌回来。
  → 实测：WS 推送走 `reload()`，而 `reload()` 在 `curBoard` 为空时直接渲染空状态 → 安全。
- 🔴 **`ensureInitialSelection()` 不再自动选板块，是**行为变更**，不只是内部实现**。
  旧行为「进入页面就看到满屏数据」被需求3 明确废除 → **依赖首屏有数据的测试都会失效**：
  `ui_check_tree.py`（筛出 0 条事项）、`ui_check_copy.py`（首屏列表未渲染）
  已同步为「先主动选板块再断言」。
  ⚠️ 后人若再改 `ensureInitialSelection`，务必同步这两个测试。
- 💡 **筛选条件跨板块保留是合理的**（人员/周数/状态是用户主动设的），
  但**列表内容必须清**。所以 `clearBoardSelection()` 只清 `curBoard`/`curYears`，
  **不清** `PERSON_SEL`/`WEEK_SEL`/状态筛选 —— 这个取舍已在代码注释里写明。
- ⚠️ **统计带取数口径变了**：从「全局汇总」变成「当前板块汇总」。
  未选板块时（`curBoard` 为空）仍显示全局 —— 这是有意的：
  用户还没选板块时给个全局概览比空白更有用。
  → 若用户认为这里也该空，需要另行拍板。
- ⚠️ **`/api/overview` 的 `board_id` 语义**：空串 = 不过滤（保持既有语义），
  非空 = 只统计该板块。外部 API 调用方不传该参数 → 行为与从前完全一致，无破坏。
