# FISP 浏览器兼容性检查报告

> 生成时间：2026-11-13 23:00 · 排查对象：`src/static/index.html`（804KB，主应用）、`src/static/login.html`（登录页）
> 排查方式：全量扫描 CSS 特性、JS API、HTML 控件、响应式断点；结合代码注释中的历史实测记录核对。
> 排查范围声明：平台为**桌面优先**应用（`html{min-width:1200px}` 锁定最小宽度），移动端不在适配目标内。

---

## 结论摘要

整体兼容性**良好**：代码风格克制，未使用大部分高危新 API；无字符串日期解析陷阱、无正则 lookbehind、无 Firefox 不支持的 `zoom` CSS。发现 **3 项需要处理的兼容性问题（P0/P1）**、**4 项优雅降级可接受项（P2）**、以及 1 项响应式隐患（旧断点块依赖层叠顺序压制）。

**基线建议**：Chrome/Edge ≥ 105、Firefox ≥ 121、Safari ≥ 15.4（这三档由 `:has()` 的支持矩阵决定，是全项目最严的约束）。若需支持更老的 Firefox/Safari，按下表 P0 方案改造即可覆盖到 Firefox ≥ 94 / Safari ≥ 14.1。

## 一、CSS 兼容性

### P0-1 `:has()` 选择器 —— Firefox < 121 完全失效（5 处）

| 位置 | 用途 | 降级表现 |
|---|---|---|
| index.html:1416 | `.tm-grp-opt:has(input:checked)` 成员角色多选高亮 | Firefox < 121：选中项**无任何高亮**，用户看不出选了谁（功能性视觉缺失） |
| index.html:2648-2674 | `.cf-field:has(.cf-chip)` / `.cf-field:has(.cf-count:not(:empty))` 筛选框内 chip 计数徽标的输入框收缩 + placeholder 隐藏 | Firefox < 121：输入框不收缩、placeholder 文字与 chip 重叠显示（布局观感破损） |

- **针对浏览器**：Firefox（121 才支持 `:has()`，ESR 老版本缺失）；Safari < 15.4、Chrome < 105 同样失效。
- **原因**：`:has()` 是关系型伪类，早期所有浏览器都不支持，Firefox 是最后实现的（2023-12 v121）。
- **修改方案**（选其一，推荐 A）：
  - **方案 A（推荐，零风险）**：JS 渲染 chip/计数时同步切换容器类名。筛选 chip 本来就是 JS 渲染的——在渲染函数里给 `.cf-field` 加/移除 `has-chips` 类，CSS 改写为：
    ```css
    .cf-field.has-chips .cf-input{flex:0 1 24px;min-width:24px}
    .cf-field.has-chips .cf-input::placeholder{color:transparent}
    .cf-field.has-count .cf-count{display:inline-flex}
    /* …其余同理；:has 版本可保留，用 @supports 包裹渐进增强 */
    ```
    角色 multi-select（1416）同理：checkbox 的 change 事件里 toggle `.on` 类。
  - **方案 B**：若确认只服务 ≥ Firefox 121 的用户，保留现状，在 2645 的注释处补充基线声明。

### P1-1 `:focus-visible` 键盘焦点环 —— Safari < 15.4 无兜底

| 位置 | 用途 |
|---|---|
| index.html:1450-1453 | `:where(button,a[href],input,select,textarea,[tabindex],[onclick]):focus-visible` 通用焦点环兜底（T-192 UI 审查引入） |
| login.html:84-86 | 登录页三处 `:focus-visible` |

- **针对浏览器**：Safari < 15.4（15.4 才支持）；Firefox 85+ / Chrome 86+ 已支持，无碍。
- **原因**：不支持的浏览器里规则整条不生效 → 键盘用户**看不到焦点在哪**（Tab 导航失明），属于可访问性回退，不影响功能。
- **修改方案**（两文件同款）：
  ```css
  /* 老浏览器兜底：不支持 :focus-visible 时退化为 :focus */
  @supports not selector(:focus-visible){
    .field input:focus, button:focus, a:focus{outline:2px solid #002D74;outline-offset:2px}
  }
  ```
  （index.html 的兜底块对应其 1450 行的选择器集合；代价是鼠标点击也会显示焦点环，可接受。）

### P1-2 `user-select` 无 `-webkit-` 前缀（17 处）

- **位置**：index.html 395, 547, 728, 793, 923, 1013, 1071, 1077, 1092, 1179, 1414, 1480, 2582, 2616, 10049（内联）, 10322（内联）；login.html:58。仅 117 行一处带 `-webkit-user-select`。
- **针对浏览器**：Safari 长期要求 `-webkit-user-select` 前缀（无前缀支持极晚）。
- **原因**：不带前缀时老 Safari 里该属性被忽略——`user-select:none` 的拖拽标题栏（.modal-header 1071）、周表头（793）等区域**文字可被意外选中**，拖动弹窗时出现蓝色选区闪烁。
- **修改方案**：批量在每处 `user-select:…` 前补 `-webkit-user-select:…`（值相同）。建议一次性 sed/脚本处理，并在项目规范里固定"写 user-select 必带 -webkit- 前缀"。

### P2-1 `accent-color` —— 勾选框/单选框品牌色（3 处，优雅降级）

- **位置**：index.html:795/797/799。
- **针对浏览器**：Safari < 15.4、Firefox < 92、Chrome < 93 不支持。
- **降级表现**：回退为**系统默认控件色**（Chrome 蓝 / Safari 蓝灰），功能完全正常，仅品牌色不统一（项目品牌色 #002D74）。
- **修改方案（可选）**：保持现状即可；若要求一致，需自绘 checkbox（自定义外观 + `:checked` 背景切换），成本较高，不建议。

### P2-2 `aspect-ratio` + `inset` —— 个人照片框（index.html:99/100）

- **针对浏览器**：`aspect-ratio` 需 Safari ≥ 15 / Chrome ≥ 88 / Firefox ≥ 89；`inset` 需 Safari ≥ 14.1 / Firefox ≥ 87。
- **降级表现**：`.profile-photo-box` 失去固定 3:4 比例 → 盒子高度塌陷为内容高度，照片预览区变成一条扁带；`img{inset:0}` 失效 → 图片定位错乱。
- **修改方案**（padding-top 兼容写法，旧浏览器也生效）：
  ```css
  .profile-photo-box{position:relative;width:100%;max-width:200px;margin:0 auto}
  .profile-photo-box::before{content:'';display:block;padding-top:133.33%} /* 3:4 */
  ```
  （`inset:0` 改回显式 `top:0;right:0;bottom:0;left:0`，一行搞定，全浏览器支持。）

## 二、JavaScript 兼容性

### P2-4 `a[download]` Blob 导出 —— Safari < 14.5 行为差异

- **位置**：index.html:12008-12022（xlsx 导出：fetch → blob → `a.download` 点击）。
- **针对浏览器**：Safari < 14.5 不支持 `download` 属性 → 点击后**在新标签页打开二进制内容**而不是保存文件。
- **修改方案（可选）**：导出前检测——
  ```js
  const isOldSafari=/^((?!chrome|android).)*safari/i.test(navigator.userAgent)
    && !/version\/1[4-9]\.|version\/[2-9]\d\./i.test(navigator.userAgent);
  if(isOldSafari)toast('当前 Safari 版本较旧，若新标签页打开请右键「存储为…」');
  ```
  或直接在文档标注基线要求（推荐，省事）。

## 四、响应式布局

### P1-3 旧断点块依赖层叠顺序压制（隐患，非现行 bug）

- **现状**：`html{min-width:1200px}`（626）锁定文档最小宽度后，`@media` 仍按**视口宽度**判定（611-616 注释里已有实测记录）。当前的修复方式（T-005）是**把同特异度的收敛块（`@media(max-width:1199px)`，约 640 行起）放在旧断点块（359-370 的 1180/900/640）之后靠层叠顺序覆盖**——窄视口时旧块先改、新块改回，净效果 = 不变形。
- **风险**：这个方案**完全依赖源码顺序**。任何人把旧块移到新块之后、或在新块中遗漏某个属性，"缩小窗口布局变形"就会复发，且非常隐蔽。
- **修改方案（推荐，一次性消除隐患）**：把 359-370 / 592 / 628 中已被 ≤1199 收敛块覆盖的规则**直接删除**（收敛块已是权威），只保留与顶部栏无关的断点；或在旧块上加显式注释 `/* ⚠️ 已被下方 ≤1199 收敛块覆盖，勿在此新增布局属性 */`。涉及块：`@media(max-width:1180px)`、`(max-width:900px)`、`(max-width:640px)`、`(max-width:1024px)`、`(max-width:1440px)`。
- **跨浏览器说明**：该问题是所有浏览器一致的（媒体查询规范行为），不属于"某浏览器专属"兼容性，但属于响应式一致性范畴，故列入。

### ✓ 其余响应式项

- `.app-header-inner` 1440 锁宽、`.topbar{min-width:1200px}`（678）：与断点收敛方案配套，正确 ✓
- `100vh` 仅 1 处（body min-height）：桌面无移动地址栏问题 ✓
- viewport meta 已设置（两文件）✓——但平台桌面优先，移动端不承诺适配
