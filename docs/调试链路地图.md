> - `E:` 源 `app.db`（约 1.2MB）是开发期误导入的**测试库**，服务不读它——**切勿同步/覆盖到 /root**。

## 三、服务是怎么拉起来的
systemd 服务文件 `/etc/systemd/system/tapd-web.service`（root 创建于 8-18）：
- `WorkingDirectory=/root/tapd_webapp`
- `ExecStart=/root/tapd_webapp/venv/bin/uvicorn app.app:app --host 0.0.0.0 --port 8000`
- `Environment=APP_SECRET=wsl-test-secret-2026`（⚠️ 非默认 secret，伪造 token 测 API 必须用这个值）
- `Restart=always`，`RestartSec=3`（挂了自动拉起 → **kill 掉也会复活，请勿手动 kill/nohup 抢端口**）

运行实况（本次核对）：进程 `active`，监听 `0.0.0.0:8000`（`ss -tlnp | grep :8000`）。

数据库现状（`/root/tapd_webapp/app.db`）：
- `boards` 表存在，含 **7 个历史看板**（8-20 由 `init_db` 从 cards 派生；新建看板也写入此表）。
- 登录账号在 `users` 表，管理员账号 `admin` 存在。
- `/root/tapd_webapp/users.json` 是 `manage_users.py` 用的独立账号文件（`E:` 源没有，**勿删**）。
- ⚠️ `init_db()` 在服务**每次启动时自动运行**（幂等：`CREATE TABLE IF NOT EXISTS`、`INSERT OR IGNORE`；**仅当 cards 表为空时才重导 CSV**）。所以：正常重启不会动数据；但**若有人清空运行库再重启，会从 `data/CSV` 自动重灌**——知晓即可，勿惊讶。

## 六、把 `E:` 的最新改动同步进运行服务（⚠️ 勿用 `--delete`）
**危险红线**：不要 `rsync --delete` 整目录同步！`E:` 源**没有 `venv/`**、其 `app.db` 是**测试库**、也没有 `users.json`；`--delete` 会删掉 `/root` 的 venv（服务直接崩）、用测试库覆盖运行库（数据灾难）。

### 方式 A（推荐，按文件拷贝——只同步代码）
```bash
wsl -d Ubuntu-24.04 -u root -- bash -c '
cd /root/tapd_webapp && \
cp "/mnt/e/WB缓存/2026-08-04-15-44-09/tapd_webapp/static/index.html" static/ && \
cp "/mnt/e/WB缓存/2026-08-04-15-44-09/tapd_webapp/app/app.py" app/ && \
cp "/mnt/e/WB缓存/2026-08-04-15-44-09/tapd_webapp/app/init_db.py" app/ && \
rm -rf app/__pycache__ static/__pycache__ 2>/dev/null; \
systemctl restart tapd-web'
```
（改哪个文件就拷哪个；`rm -rf __pycache__` 防止旧字节码被误用，务必保留；每次改完必须 `systemctl restart tapd-web`）
> 若在 `E:` 源**删除了某个文件**，请手动同步删除 `/root` 对应文件（rsync 无 `--delete` 不会自动清）。

### 方式 B（rsync，禁用 --delete 并显式排除数据/环境）
```bash
wsl -d Ubuntu-24.04 -u root -- bash -c '
rsync -a \
  --exclude=venv --exclude=app.db --exclude=users.json --exclude=data \
  --exclude=__pycache__ --exclude="*.pyc" --exclude=uvicorn.log \
  "/mnt/e/WB缓存/2026-08-04-15-44-09/tapd_webapp/" /root/tapd_webapp/ && \
systemctl restart tapd-web'
```

### 同步后必须验证（四连：**特征字符串第一，版本注释只是辅助**）
```bash
systemctl is-active tapd-web                                   # ① active
curl -s localhost:8000/ | grep -c "<本次改动的唯一特征字符串>"   # ② ★第一验证：新函数名/新 id/新文案
curl -s localhost:8000/ | grep -o "2026-08-20 09:52"            # ③ 仅辅助：版本注释（改码时同步更新第 9 行）
journalctl -u tapd-web -n 20 | grep -i "error\|traceback"      # ④ 无启动报错
```
> ⚠️ **验证盲区提醒**：只 grep 版本注释不可靠——若忘了更新注释，旧字符串仍能匹配，会**误判"已生效"**（实际跑旧代码）。**必须以 ② 特征字符串为准**；注释 `③` 仅当 ② 失败时用来排查"是否同步/重启失败"。

### crash-loop 处理（重要）
重启后若 `systemctl is-active` 显示 `activating`/`failed` 反复横跳、端口不通 → 说明代码有启动错误（语法/导入/DB 问题）：
```bash
systemctl stop tapd-web          # 先停住，停止 3 秒重启循环
journalctl -u tapd-web -n 50     # 看报错定位
# 修好 E: 源 → 本地语法检查 → 同步 → systemctl start tapd-web
```
**严禁**在这种情况下用 nohup/kill 硬来。

## 九、管线安全红线（防止伤害管线/项目 —— 本链路的安全边界）
1. **同步只覆盖代码，永不碰**：`venv/`、`app.db`（/root 运行库）、`users.json`、`data/`。禁用 `rsync --delete`。
2. **数据/账号操作一律在 `/root/tapd_webapp` 下进行**（运行库所在地）；**禁止在 `E:` 源运行 `init_db.py` / `manage_users.py`**——它们操作的是 E: 测试库，服务不读，会造成"改了没生效"的误导。
3. **重启只走 `systemctl restart tapd-web`**；`kill` 会被 systemd 3 秒拉起，`nohup` 必绑定失败。crash-loop 用 `systemctl stop` 先停。
4. **改后端必须先 `py_compile`**，语法错误会导致服务 crash-loop（端口不可用、日志刷屏）。
5. **验证以"特征字符串 grep"为准**，版本注释仅辅助（避免误判"已生效"）。
6. 运行库被清空时重启会自动重导 `data/CSV`（init_db 行为）——清库前先确认是否有意为之。

## 十、已知坑（血泪清单）
- **systemd 托管**：`kill` 后 3 秒自动拉起；`nohup` 手动起必绑定失败。**一切重启走 `systemctl restart tapd-web`**。
- **APP_SECRET 非默认**：`wsl-test-secret-2026`。默认 secret 伪造的 token 必 401。
- **`index.html` 为 CRLF**：字符串匹配/替换前先归一化 `\n`。

- **E: 源 app.db 是测试库**：别同步、别当运行库；运行库只在 `/root/tapd_webapp/app.db`。
- **版本注释只是标识**：判断"本次改动是否生效"靠特征字符串 grep，别只信注释。

### API token 伪造模板（E2E 测试用，已加容错）
```python
# WSL root 下运行；SECRET 必须用服务环境值
import json, base64, hmac, hashlib, time, urllib.request, urllib.error
SECRET="wsl-test-secret-2026"
def b64e(b): return base64.urlsafe_b64encode(b).rstrip(b"=").decode()
body=b64e(json.dumps({"u":"admin","exp":int(time.time())+3600}).encode())
sig=b64e(hmac.new(SECRET.encode(),body.encode(),hashlib.sha256).digest())
token=body+"."+sig
req=urllib.request.Request("http://localhost:8000/api/me", headers={"Authorization":"Bearer "+token})
try:
    r=urllib.request.urlopen(req); print(r.status, r.read().decode()[:200])
except urllib.error.HTTPError as e:
    print("HTTPError:", e.code, e.read().decode()[:200])
```
