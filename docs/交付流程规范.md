# TAPD 工作台 · 交付流程规范

> 生效日期：2026-10-26
> 核心原则：**代码变更必须先在本地完成并通过验证，由用户手动触发才同步到远程环境。**

---

## 流程总览

```
   ┌─────────────────────────────────────────────────────────┐
   │  阶段一：本地执行与验证（强制前置）                        │
   │                                                         │
   │   改代码 → ops/verify.py → 7 项检查全通过 → 签发验证凭证  │
   │                                              .verify-stamp│
   └──────────────────────────┬──────────────────────────────┘
                              │
                    ✗ 未通过 │ 拒绝
                              │
   ┌──────────────────────────▼──────────────────────────────┐
   │  阶段二：手动触发热同步（仅用户手动执行）                 │
   │                                                         │
   │   ops/sync.sh --dev / --prod                            │
   │   → 门禁校验凭证（指纹 + 时效）                          │
   │   → 校验通过才推送 → 服务器重启生效                      │
   └─────────────────────────────────────────────────────────┘
```

**两个阶段严格分离**：阶段一不碰远程，阶段二不接受未验证的代码。

## 阶段一：本地执行与验证

### 触发方式

```bash
cd E:\WB缓存\2026-10-26-15-55-08\ops
python verify.py
```

（Windows 上若 `python` 不在 PATH，用 `D:\py\python.exe verify.py`；
或用 venv 里的 `.\.localvenv\Scripts\python.exe verify.py`）

### 验证通过的标准

**7 项检查全部通过，且不产生任何 ERROR 级输出**。逐项说明：

| # | 检查项 | 通过标准 | 失败意味着 |
|---|---|---|---|
| 1 | **Python 语法编译** | `py_compile app/app.py app/init_db.py` 返回 0 | 服务会 crash-loop，端口不可用 |
| 2 | **JS 语法检查** | 抽出 `index.html` 的所有 `<script>` 块跑 `node --check` 通过 | 前端白屏，页面完全不可用 |
| 3 | **依赖完整性** | `requirements.txt` 里每个包都能 import | 服务器装依赖时会失败或运行时 ImportError |
| 4 | **应用可导入** | `importlib.import_module('app.app')` 成功，FastAPI 实例存在、路由数 > 0 | 启动即崩 |
| 5 | **数据库完整性** | `PRAGMA integrity_check` == `ok` | 数据损坏，读写会报错 |
| 6 | **端到端冒烟** | 起临时服务 → 登录 → `/api/me` `/api/boards` `/api/board-config` 全 200 → xlsx 导出成功且**零合并单元格** | 核心链路不通 |
| 7 | **git 工作区状态** | 有未提交改动时**仅警告不阻断** | — |

第 6 项是核心保障：它会真的起一个服务、真的登录、真的导出 xlsx、真的用 openpyxl 检查合并单元格数为 0。**不是走过场。**

### 凭证机制

全部通过后签发验证凭证 `ops/.verify-stamp`：

```json
{
  "fingerprint": "433ad9bc317d6bd16b351cbd6abef896...",
  "verified_at": "2026-10-26 17:51:20",
  "timestamp": 1793043080
}
```

- **fingerprint** = 对 `app/` + `static/` + `requirements.txt` + `manage_users.py` 全部文件内容取 SHA-256
  （**只看内容，不看 mtime**，所以 touch 文件不会误判，改内容一定会变）
- **timestamp** = 签发时间戳，用于时效判断

### 快捷选项

```bash
python verify.py --quick        # 跳过端到端冒烟（1~5、7 项，约 5 秒）
python verify.py --stamp-only    # 不做检查，只按当前代码重新签发凭证
```

> `--quick` 适合"代码没动、只是凭证过期想续期"的场景。
> **涉及逻辑改动的变更请跑完整验证**（不加 `--quick`）。

## 阶段二：手动触发热同步

### 触发方式

**必须由你手动执行**，不由任何自动化流程代劳：

```bash
cd E:\WB缓存\2026-10-26-15-55-08\ops

./sync.sh --dev     # 推送到服务器开发环境（重启 tapd-dev）
./sync.sh --prod    # 推送到生产环境（重启 tapd-web）
```

### 门禁规则

`sync.sh` 在推送前**强制校验验证凭证**，任一不满足即拒绝同步：

| 情况 | 结果 | 提示 |
|---|---|---|
| 没有 `.verify-stamp` | **拒绝** | 「阶段一尚未完成，请先运行 python verify.py」 |
| 凭证指纹 ≠ 当前代码指纹 | **拒绝** | 「代码已变更，验证凭证失效」 |
| 凭证超过 2 小时 | **拒绝** | 「验证凭证已过期」 |
| 凭证损坏 | **拒绝** | 「验证凭证无效」 |
| 全部满足 | 放行 | 「✓ 验证凭证有效 <时间>」 |

**拒绝时不会发生任何推送**——脚本在 scp 之前就退出了，服务器代码完全不受影响。

### 时效可调

```bash
VERIFY_MAX_AGE=14400 ./sync.sh --dev    # 放宽到 4 小时
```

### 紧急绕过（仅限故障恢复）

```bash
SKIP_VERIFY=1 ./sync.sh --dev
```

会打印醒目警告。**只在"线上出故障、需要立刻推个补丁"时用**，用完请重新跑 `verify.py` 补上凭证。

### 例外：`--pull` 不受门禁约束

`./sync.sh --pull` 是**从服务器往回拉**，不涉及推送，因此不校验凭证。
（服务器上直接改过代码、需要把改动拉回本地时用这个。）

## 「验证未通过时不得触发同步」的约束

这是硬约束，由三层机制共同保证：

### 第 1 层：凭证不签发

`verify.py` 只要有**任何一项**失败，就**不写 `.verify-stamp`**，并以非 0 退出码结束：

```
  ✗ [1] Python 语法编译
  ✓ [2] JS 语法检查  2 个 script 块
  ✗ [4] 应用可导入  SyntaxError: invalid syntax

✗ 验证未通过：4/6 项通过
  禁止执行 sync.sh —— 请先修复上述失败项
  失败项: Python 语法编译, 应用可导入
```

### 第 2 层：同步入口拦截

没有凭证 → `sync.sh` 在第一步就退出，**根本走不到 scp**。

### 第 3 层：内容指纹绑定

**即使凭证已签发，之后又改了代码，指纹也会变**，同步同样被拒：

```
✗ 代码已变更，验证凭证失效，拒绝同步
  指纹 433ad9bc317d -> 95cc9eca7e7c
  阶段一需重跑： cd ops && python verify.py
```

这防的是"验证完又偷偷改了代码，然后直接同步"。

### 实测记录

| 场景 | 预期 | 实测 |
|---|---|---|
| 无凭证 | 拒绝 | ✓ 拒绝，服务器代码未变（1681 行不变） |
| 验证失败（注入语法错误） | 拒绝 + 不签发凭证 | ✓ 拒绝，凭证文件不存在 |
| 验证后改代码 | 拒绝 | ✓ 拒绝，指纹不匹配 |
| 凭证过期 | 拒绝 | ✓ 拒绝 |
| 有有效凭证 | 放行 | ✓ 放行，同步成功 |
| `--pull` | 不受限 | ✓ 正常拉取 |

## 完整工作流示例

```bash
# ── 阶段一：本地执行与验证 ─────────────────────────────
cd E:\WB缓存\2026-10-26-15-55-08\src
vim app/app.py                      # 改代码
git add -A && git commit -m "修复卡片编辑锁超时"   # 记录版本

cd ../ops
python verify.py                    # ← 7 项检查，全过才签发凭证

# ── 阶段二：手动触发热同步（你亲自执行）─────────────────
./sync.sh --dev                     # 推到开发环境，浏览器验证
# 确认没问题后
./sync.sh --prod                    # 推到生产环境
```

## 常见问题

| 现象 | 处理 |
|---|---|
| `✗ 没有验证凭证` | 跑 `python verify.py` |
| `✗ 代码已变更` | 跑 `python verify.py` 重新验证 |
| `✗ 验证凭证已过期` | 跑 `python verify.py`；急用可 `VERIFY_MAX_AGE=86400` |
| 验证第 6 项失败但看不出原因 | 手动起服务看日志：`cd ops && ./local-dev.sh` |
| 改完代码想跳过端到端测试 | `python verify.py --quick`（但 1~5 项仍会跑） |
| 线上要紧急打补丁 | `SKIP_VERIFY=1 ./sync.sh --dev`，事后补跑 verify.py |
